# Guidance: dsagent.settings

Owner rules for planning with these methods, each paragraph once with the methods it applies to. They are projections of the owner descriptors (the live `guidance` field); the per-method references link here.

- (dsagent.settings.get) Without workflowId: the Extension settings (export-directory, dom-training-export, trace-logs, intent-interpreter, ad-blocker-default, fallback-model, execution-memory, site-memory, site-notes, resource-pressure, professional-mode, identity-providers, run-window-focus, agent-challenge-walls, browser-monitor, file-release-consent, notification-channels, schedules, llm-models, chat-model, mail, dashboard-url). With workflowId from dsagent.workflows.list: that workflow's card settings (workflow-favorite, workflow-run-environment, workflow-name, workflow-sheet-binding, workflow-record-limits, workflow-monitors). Each section lists the operations dsagent.settings.update accepts and the parts only the person may change; a section the person lacks the SidePanel permission for, or whose owner is unreachable, reports unavailable instead of a value. API keys, secrets and account tags are never returned.

- (dsagent.settings.update) Read the section with dsagent.settings.get first; pick the operation it lists and send the value shaped like the matching oneOf branch. set merges into the current value unless the branch says otherwise; create returns the new itemId. Parts listed as personOnly (credentials, physical paths, arbitrary URLs) fail with PERSON_ONLY_SETTING and must be changed by the person. Requires an idempotency key; repeating a key with the same request replays its result.
