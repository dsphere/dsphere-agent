# Guidance: dsagent.dataset

Owner rules for planning with these methods, each paragraph once with the methods it applies to. They are projections of the owner descriptors (the live `guidance` field); the per-method references link here.

- (dsagent.dataset.save-agent-read) Use it only when auto detection, detect-with-ai and pick-sample-record have all failed: cite the wizard (wizardId, wizardToken), the typed endpoint it ended on (endpoint = dsagent.wizard.state lastEndpoint.endpoint, e.g. structure-none or ai-found-nothing, admitted only when lastEndpoint.agentReadAdmissible is true) and pageContextId of the page you read (the page of that wizard, or a sample page it opened). When dsagent.wizard.start refused the page itself (details.endpoint page-not-scrapable or session-start-refused with details.agentReadAdmissible true), cite its details.refusalId as wizardId and that endpoint instead: the refusal is the typed detection failure for that page. Never for a sign-in or verification wall: that waits for the person. Records are flat objects of page values (string, number, boolean or null); the Extension normalises field names, drops credential and payment fields, redacts credential-shaped values and enforces the size limits. The dataset is labelled source agent-read, replayable false, with its coverage (recordsSaved counted by the Extension; expectedRecords, pagesVisited and stoppedBecause as you state them): report it as agent-read, never as a workflow result. It creates or updates no workflow and cannot be run again. One save holds at most 500 records; save more to the same capture with captureId and the captureToken the first save returned. Read the dataset back with dsagent.artifacts.list (executionId = captureId) and dsagent.artifact.read, or export it with dsagent.execution.data.export. Requires an idempotency key; repeating a key with the same input returns the same result.
