# Guidance: dsagent.development

Owner rules for planning with these methods, each paragraph once with the methods it applies to. They are projections of the owner descriptors (the live `guidance` field); the per-method references link here.

- (dsagent.development.chat.send) For live checks of the Chat the person asked you to run. Only when the person explicitly asked you to use the Chat, and only while the person's grant is on (SidePanel Settings, development builds, one hour; no capability can turn it on): without it every call is refused with POLICY_DENIED (CHAT_AGENT_ACCESS_NOT_GRANTED). Never use the Chat to run your own work: the Chat is the person's autonomous task path. Refused with TARGET_BUSY while a reply streams (CHAT_BUSY) or a browser task of the Chat runs (CHAT_TASK_RUNNING: typed text would be that task's guidance); with CAPABILITY_UNAVAILABLE when no model is selected (CHAT_NO_MODEL) or no SidePanel answered (SIDEPANEL_UNAVAILABLE). Follow the task with dsagent.development.chat.state, dsagent.pages.list and dsagent.executions.list. Requires an idempotency key.

- (dsagent.development.chat.state) Only when the person explicitly asked you to use the Chat, and only while the person's grant is on (SidePanel Settings, development builds, one hour; no capability can turn it on): without it every call is refused with POLICY_DENIED (CHAT_AGENT_ACCESS_NOT_GRANTED). Never use the Chat to run your own work: the Chat is the person's autonomous task path.

- (dsagent.development.inject-fault) kind=sqlite-lost-ack makes the next `times` dataset commits of this browser succeed on disk but lose their acknowledgment, so the workflow run retries them from its durable outbox (L8): the flush gives the lost acknowledgment one attempt, then the outbox retry gives it three rounds: times 1 to 3 recover the rows on the retry (coverage.rowsRecovered), times 4 or more exhaust it and the run reports rowsUnsaved. kind=sqlite-clear disarms it. kind=run-tab-group-closed closes every tab of the running execution's tab group as a person closing the group would, so the run reopens its page and resumes at its loop (L7), with its interrupted parallel items handed to you after the group. Faults stay armed until spent or cleared and affect every run of this browser: arm one right before the run that must meet it and clear it afterwards. Requires an idempotency key.

- (dsagent.development.reload-extension) Pass the engineRevision printed in dist/browser-engine-identity.json after the build: the call is a no-op when that revision already runs, refuses when the folder holds a different revision (build still writing or another build), and refuses while workflow executions or SidePanel Chat autonomous runs are active unless force is true. After status=reloading the reply is sent first, the Extension reloads after reloadDelayMs and the browser-hosted Native Agent restarts: expect EXTENSION_OFFLINE for a few seconds, then call again with the same expectedEngineRevision until status=already-current. Requires an idempotency key.

- (dsagent.development.restart-service-worker) chrome.storage.session, tabs, open scrape and recording sessions and persisted wizard records survive; in-memory state and the browser-hosted Native Agent runtime do not. Unlike dsagent.development.reload-extension (a cold start that clears chrome.storage.session), this is the restart the browser itself performs. Advertised only by development builds, runs only for an unpacked install, and keeps the running bundle: expectedEngineRevision must equal the running engineRevision. After status=restarting the worker closes its Native connection and goes idle; the browser stops it after about 30 s without events, and a new worker starts on the next browser event or on the wake-up alarm 2 minutes later (a worker still running then was kept busy, and the Extension is reloaded instead). Expect EXTENSION_OFFLINE meanwhile and leave the browser alone, then call again with restartedFrom set to the workerId of this reply until the status is restarted (a hot restart: chrome.storage.session kept the restart marker) or reloaded (the browser did not end the worker, so the Extension was reloaded instead: a cold start, not a hot restart). Guided wizards do not block it (they resume from their records); workflow executions and SidePanel Chat autonomous runs do unless force is true. Requires an idempotency key.
