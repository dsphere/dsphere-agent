# Guidance: dsagent.development

Owner rules for planning with these methods, each paragraph once with the methods it applies to. They are projections of the owner descriptors (the live `guidance` field); the per-method references link here.

- (dsagent.development.chat.arm) A task already running keeps the arm it started with; each task's chat-tool-planner.harness trace event names its arm. Only while the person's Chat grant is on (POLICY_DENIED CHAT_AGENT_ACCESS_NOT_GRANTED otherwise). Clear it when the benchmark ends. Requires an idempotency key.

- (dsagent.development.chat.new) Only when the person explicitly asked you to benchmark or live-check the Chat, and only while the person's grant is on (SidePanel Settings, development builds, one hour; no capability can turn it on): without it every call is refused with POLICY_DENIED (CHAT_AGENT_ACCESS_NOT_GRANTED). Refused with TARGET_BUSY while a reply streams (CHAT_BUSY) or a browser task of the Chat runs (CHAT_TASK_RUNNING). Requires an idempotency key.

- (dsagent.development.chat.respond) Development only: answer the decision the Chat task's card waits on, as the person would: decision approve-plan presses Start (or Continue) on the waiting plan of that version; decision answer answers the open question with that requestId (accepted, and optionIndex for an option or answer for free text). Read the pending decision first with dsagent.development.chat.transcript. Only when the person explicitly asked you to benchmark or live-check the Chat, and only while the person's grant is on (SidePanel Settings, development builds, one hour; no capability can turn it on): without it every call is refused with POLICY_DENIED (CHAT_AGENT_ACCESS_NOT_GRANTED). Refused with TARGET_NOT_FOUND (CHAT_DECISION_NOT_PENDING) when the task waits on no such plan version or question, and with INVALID_REQUEST (CHAT_ANSWER_REJECTED) when the task refused the answer. Requires an idempotency key.

- (dsagent.development.chat.send) For live checks of the Chat the person asked you to run. Only when the person explicitly asked you to use the Chat, and only while the person's grant is on (SidePanel Settings, development builds, one hour; no capability can turn it on): without it every call is refused with POLICY_DENIED (CHAT_AGENT_ACCESS_NOT_GRANTED). Never use the Chat to run your own work: the Chat is the person's autonomous task path. Refused with TARGET_BUSY while a reply streams (CHAT_BUSY) or a browser task of the Chat runs (CHAT_TASK_RUNNING: typed text would be that task's guidance); with CAPABILITY_UNAVAILABLE when no model is selected (CHAT_NO_MODEL) or no SidePanel answered (SIDEPANEL_UNAVAILABLE). Follow the task with dsagent.development.chat.state, dsagent.pages.list and dsagent.executions.list. Requires an idempotency key.

- (dsagent.development.chat.state) Only when the person explicitly asked you to use the Chat, and only while the person's grant is on (SidePanel Settings, development builds, one hour; no capability can turn it on): without it every call is refused with POLICY_DENIED (CHAT_AGENT_ACCESS_NOT_GRANTED). Never use the Chat to run your own work: the Chat is the person's autonomous task path.

- (dsagent.development.chat.stop) Only when the person explicitly asked you to benchmark or live-check the Chat, and only while the person's grant is on (SidePanel Settings, development builds, one hour; no capability can turn it on): without it every call is refused with POLICY_DENIED (CHAT_AGENT_ACCESS_NOT_GRANTED). Refused with TARGET_NOT_FOUND (CHAT_TASK_NOT_FOUND) when the open conversation has no such task of the Chat (an outside agent's mirrored task is stopped by its own agent). Requires an idempotency key.

- (dsagent.development.chat.transcript) Development only: the open conversation of the focused window's Chat with each message's text (cut at 8000 characters), its task's status, what the observed task waits on (a plan to approve or a question, read before dsagent.development.chat.respond) and, with traceSessionId, that task's redacted trace events, oldest first (event names and bounded details, never prompts or page text). When the panel shows another view (the live run view a task's run switches to), the read brings the Chat back into view once; panelOpen false when still no Chat answered. Only when the person explicitly asked you to benchmark or live-check the Chat, and only while the person's grant is on (SidePanel Settings, development builds, one hour; no capability can turn it on): without it every call is refused with POLICY_DENIED (CHAT_AGENT_ACCESS_NOT_GRANTED).

- (dsagent.development.inject-fault) kind=sqlite-lost-ack makes the next `times` dataset commits of this browser succeed on disk but lose their acknowledgment, so the workflow run retries them from its durable outbox (L8): the flush gives the lost acknowledgment one attempt, then the outbox retry gives it three rounds: times 1 to 3 recover the rows on the retry (coverage.rowsRecovered), times 4 or more exhaust it and the run reports rowsUnsaved. kind=sqlite-clear disarms it. kind=run-tab-group-closed closes every tab of the running execution's tab group as a person closing the group would, so the run reopens its page and resumes at its loop (L7), with its interrupted parallel items handed to you after the group. Faults stay armed until spent or cleared and affect every run of this browser: arm one right before the run that must meet it and clear it afterwards. Requires an idempotency key.

- (dsagent.development.restart-service-worker) chrome.storage.session, tabs, open scrape and recording sessions and persisted wizard records survive; in-memory state and the browser-hosted Native Agent runtime do not. Unlike an Extension reload (a cold start that clears chrome.storage.session), this is the restart the browser itself performs. Advertised only by development builds, runs only for an unpacked install, and keeps the running bundle: expectedEngineRevision must equal the running engineRevision. After status=restarting the worker closes its Native connection and goes idle; the browser stops it after about 30 s without events, and a new worker starts on the next browser event or on the wake-up alarm 2 minutes later (a worker still running then was kept busy, and the Extension is reloaded instead). Expect EXTENSION_OFFLINE meanwhile and leave the browser alone, then call again with restartedFrom set to the workerId of this reply until the status is restarted (a hot restart: chrome.storage.session kept the restart marker) or reloaded (the browser did not end the worker, so the Extension was reloaded instead: a cold start, not a hot restart). Guided wizards do not block it (they resume from their records); workflow executions and SidePanel Chat autonomous runs do unless force is true. Requires an idempotency key.

- (dsagent.development.sidepanel.action, dsagent.development.sidepanel.observe, dsagent.development.sidepanel.open) No selectors, scripts, field values, credentials, saves, permission changes or confirmation acceptance. Initially supports Accounts quick actions and creation sheets. Use only for UI checks requested by the person; not for the Chat planner.
