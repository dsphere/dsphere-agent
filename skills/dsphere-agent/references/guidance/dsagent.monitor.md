# Guidance: dsagent.monitor

Owner rules for planning with these methods, each paragraph once with the methods it applies to. They are projections of the owner descriptors (the live `guidance` field); the per-method references link here.

- (dsagent.monitor.assist) While it lasts (5 minutes; start again to renew) your dsagent.page.action / actions / focus are admitted there although the page is not yours; the page stays its owner's. Walls stay decided as on your own pages: a verification challenge is yours to pass under its attempt budget while the person's Verification Challenges switch is on, a sign-in wall is never yours. When the page is clear, end the assist: if the wall is verified gone, the task or run that waited on it continues. An assist ends by itself once nothing holds the page up any more (refused then with MONITOR_ASSIST_ENDED), when it lapses, when your connection ends or when the person turns the monitor off. Refusals: ASSIST_NOT_NEEDED (act directly), NOT_BLOCKED (its owner works; leave it), ASSIST_HELD (another agent assists), MONITOR_OFF. Requires an idempotency key.

- (dsagent.monitor.snapshot) Use it to watch what runs, report what went wrong (attention) and help where an owner is held up: pass a verification challenge, dismiss what covers a page, bring a failed task's page back to a usable state, tell the person (dsagent.page.notify) what needs them. Follow changes with dsagent.events.open topics [monitor] instead of polling. Reads of any page are shared (dsagent.page.observe / find / markdown on any pageContextId); to act on a page another owner holds, start an assist first (dsagent.monitor.assist). Never pass a sign-in wall, enter credentials or answer another task's question for the person. Read-only. Pages that need attention come first. The person can turn the monitor off (Settings, Browser Task Monitor): then it is refused POLICY_DENIED MONITOR_OFF.
