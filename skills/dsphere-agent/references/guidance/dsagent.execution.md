# Guidance: dsagent.execution

Owner rules for planning with these methods, each paragraph once with the methods it applies to. They are projections of the owner descriptors (the live `guidance` field); the per-method references link here.

- (dsagent.execution.artifact.export) Reuse executionId from the error details and the original artifactId, write the artifact to the Extension-managed directory, then analyze the returned local path without inlining the full content.

- (dsagent.execution.data.export) Write the records a finished execution collected (for example one started by dsagent.wizard.run, once dsagent.execution.wait reports it terminal) as UTF-8 CSV files in the Extension-managed directory, one file per dataset table: a list with details, such as posts and their comments, gives one file per table, and every row carries 记录ID, 父记录ID and 层级 so child rows join their parents. Analyze the returned local paths without inlining their content. Requires an idempotency key; repeating a key with the same input returns the same files.

- (dsagent.execution.get) A run in this browser reports its pause (a sign-in wall with who must act and until when, host pressure with its way out, or your repair handoff), its progress and its pages; a terminal run reports how it ended (endpoint, node, coverage, stop source), read back from the DSphere backend for a run in another browser.

- (dsagent.execution.handoff.get) Read the bounded, redacted context of a run paused for your repair (pause.kind agent-repair of dsagent.execution.get / wait; failure-endpoint fallback tier E3): the typed endpoint the block failed on, the block, the element it was recorded on (tag, role, label, intent; never a selector), the loop item, the in-run recovery's decline, the answers accepted and the deadline. With candidates (default true) it also lists the page targets that read like the recorded element, best first, from the page observation owner (opaque targetId and revision as dsagent.page.find issues them): evidence for your own choice, never the Extension's; a retry retarget is still verified against the recorded identity (for a control renamed on purpose, say identityChangeIntended in dsagent.execution.handoff.resume). With vision true (only when you read images) it adds one redacted screenshot of the run page's viewport. Only the agent that started the run may read or answer it (after a restart of your Connector, pass runToken once and the run follows your new connection); the person may answer the same handoff in the SidePanel, and the first answer wins. While the run waits, its pages (pause.pageContextId) are yours to observe and act on with dsagent.page.* (dismiss an overlay, scroll, bring the target into view; never pass a sign-in or verification wall: that is the person's). Then answer with dsagent.execution.handoff.resume or end it with dsagent.execution.handoff.abort. At most 5 handoffs per run and one per block and loop item; an unanswered handoff ends the run failed after 10 minutes. Read-only.

- (dsagent.execution.handoff.resume) With retarget, retry rebinds the block to the element you choose by its page target (targetId and targetRevision of a dsagent.page.observe / find of pageContextId): the Extension derives the address and verifies the element against the block's recorded identity, and the run uses it for the rest of this run only (never the saved workflow); a refused retarget (RETARGET_REFUSED) leaves the handoff open. retarget.remember true confirms it may be filed in healing memory for later runs once the retried block completes; otherwise it stays a proposal. When the control was renamed on purpose (its label or identity changed, so the retarget is refused with reason identity-unverified), retarget again with identityChangeIntended true: the Extension still derives and checks the address from your target, accepts the changed identity for this run only and records it (in the run log, in identityChange of this answer and in the answer record of the handoff); it never rewrites the saved workflow. skip-item: leave the loop item (only inside a loop item): it is not collected, so the run writes no row for it and takes back any row the item already saved; coverage counts it in itemsSkipped. continue: go on to the next blocks because the block's effect did happen (you checked the page; for an unverified click or upload the Runner never repeats it by itself); the run records that it continued past an unverified block. A block that fails again after retry ends the run (one handoff per block and loop item). Requires an idempotency key.

- (dsagent.execution.wait) A run in this browser is followed from its own runtime without backend polling and reports progress with movedDuringWait; call again while terminal is false.
